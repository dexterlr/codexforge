# Canonical layered composition, version 1

The Studio owns editorial data. Original Asset identities and bytes remain immutable. A Take references an exact Asset version; selecting it is an editorial preference, not a command to replace a shot, remove another Take, approve rights or QC, or execute a provider.

The hierarchy is Project → Sequence → Shot → ShotComposition → ordered Layers → original Asset versions. A project can also contain PRECOMP compositions referenced by nested layers. PRECOMP identity is independent of a Shot. Sequence/master timeline data is a separate future editorial schema, not another interpretation of a ShotComposition.

Version 1 stores VIDEO, IMAGE and NESTED_COMPOSITION layers. Array order is the only painter order (first bottom, last top). Timing uses exact integer microseconds and half-open intervals. A layer stores its start, duration and source offset independently, with position, scale, rotation, normalized anchor, opacity, enabled/locked/solo state and explicit editorial provenance. Locking restricts modification; it never hides the layer. Enabled solo layers suppress nonsolo layers in the same composition. Disabled solo layers do not suppress anything. Layer and composition approval remain DRAFT; review never changes an immutable source's approval.

Transforms describe a source fitting the composition's frame before layer transforms are applied. Position is in parent-composition pixels; anchor is normalized to that fitted frame; scaling and rotation occur around that anchor. Nested compositions first render at their own dimensions and become a source for the parent layer. Sources are referenced, not copied when reused or nested.

Schema v1 accepts only playbackRate 1, reverse false and an empty keyframes array. Crops, blend modes, mattes, masks, effects, audio processing, depth/3D, expressions, and other unsupported fields/types are rejected rather than silently ignored. The reusable future keyframe design is a typed property registry with numeric values, exact times and HOLD/LINEAR/BEZIER interpolation; activating tracks requires a new validated schema and a renderer that actually evaluates them. No arbitrary property paths, JavaScript or expression evaluation is accepted. Additional source/effect/layer variants can extend discriminated contracts without flattening existing layers or changing original Asset identities.

Nested references must resolve within the same project, point to PRECOMP records, fit the referenced duration, and form an acyclic graph of at most eight levels. Validation uses memoized graph depth (O(compositions + layers)), not expansion of every path in a shared graph. Current bounds are 32 compositions, 32 layers per composition, 128 Takes, one-hour timelines and 16,384-pixel dimensions, additionally subject to existing JSON/repository bounds. These do not raise media import or native filesystem limits.

An offline source is runtime availability state, not a destructive editorial mutation. Missing storage must leave AssetRef, Take, layer timing and transforms intact, show affected layers offline, and revalidate exact source identity and bytes after reconnection. It must not substitute media or silently create a replacement library. A proxy/thumbnail/waveform is a future alternate representation of the original identity, not a replacement layer source.

Rendering is a future explicit operation that produces a NEW Asset version from an exact composition snapshot and output specification. A simple browser preview is not an exported master, technical QC pass, or professional timeline implementation. After Effects/Premiere are future translation/execution adapters; neither application file format becomes Studio persistence. Provider identity remains provenance, never the editor's source model.

`composition-contract.ts` is pure validation and visibility logic. Persistence owns compare-and-swap, exact edit receipts, revision/audit binding, immutable source checks and human-edit authorization. Its context parameter must come from a previously validated canonical repository snapshot, never from a client-provided object.

The first UI is on `/animation-studio`, alongside the existing project, shot and local-footage panels. It offers an explicit silent browser-seek viewer, a layer stack and property inspector, not continuous synchronized playback, audio mixing or a final export. Local MP4 import is supported; the image viewer accepts already-registered PNG/JPEG Assets. There is no image-import or editable-text interface in this phase. Unsupported nested preview stops explicitly rather than silently omitting its layers.

Saved editorial history uses immutable content-addressed records and a compare-and-swap head, fenced to the project manifest. A missing head plus any retained editorial directory is unavailable, not a new empty edit. One exact original first-save request may restore a sole byte-identical first-revision record under the unchanged project fence; multiple, empty or corrupt orphan histories are not guessed or rewound. Such ambiguous storage damage requires an explicit future recovery procedure. Interrupted saves preserve their exact body/key in browser session storage; no automatic retry occurs, even when metadata cannot be loaded. Failed metadata and recovery-storage errors are reported independently, and a definitive server rejection cannot discard the only retained copy of an edit.
